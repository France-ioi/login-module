# Profile, verification and personal data

## Profile attributes

### The schema

Every profile attribute is a public static method of `App\LoginModule\Profile\SchemaConfig`: adding a
method adds an attribute (`SchemaBuilder::availableAttributes()` lists the class methods). Each method
returns:

| Key | Meaning |
|---|---|
| `type` | form element: `text`, `select`, `email`, `checkbox`, `radios`, `date`, `textarea`, `picture`, `login`, `public_info`, `public_name` |
| `required` | rules applied only when the platform requires the attribute |
| `valid` | rules always applied |
| `options` | choices of `select` / `radios` |
| `label`, `help`, `name` | display overrides |
| `prepend`, `append` | another attribute rendered with this one (they share its required/recommended flags) |

| Attribute | Type | Rules / notes |
|---|---|---|
| `login` | login | 3–30 chars; new logins match `profile.login_validator.new` (`[a-z0-9-]`); unique; `not_historical_username` (former logins can't be reused) |
| `first_name`, `last_name` | text | max 100 |
| `graduation_grade` | select | `trans('graduation_grades')`: -1 "don't want to say", -2 "already graduated", 0..11; the label shows the school year |
| `graduation_year` | text | required when grade is -2; between now-100 and now+30 |
| `nationality`, `country_code` | select | ISO codes from `trans('countries')` |
| `role` | select | student / teacher / other |
| `primary_email`, `secondary_email` | email | unique; required only for accounts not generated by a platform (`creator_client_id` null); secondary must differ from primary |
| `language` | select | `config('app.locales')` |
| `address`, `city`, `zipcode`, `primary_phone`, `secondary_phone` | text | GDPR attributes (see below) |
| `timezone` | select | `trans('timezones')` |
| `birthday` | date | `Y-m-d`, before today; kept in sync with `birthday_year` |
| `birthday_year` | text | integer, now-100..now |
| `gender` | radios | m / f / o |
| `presentation`, `website`, `student_id` | textarea / text | |
| `subscription_results`, `subscription_news`, `real_name_visible` | checkbox | a hidden `0` input is emitted before each checkbox |
| `picture` | picture | image, max `ui.profile_picture.max_file_size` MB; resized to 200×200 |
| `public_info`, `public_name` | display only | what other users see |

`SchemaConfig` still contains commented-out attributes (teacher domain, ministry of education, school grade).

### Building a form

`SchemaBuilder::build($user, $required, $recommended, $disabled, $unverified, $hidden)` returns a
`Schema` of blocks. Hidden attributes are skipped, disabled ones get no rules and are not fillable.
`Schema::rules()` and `fillableAttributes()` drive validation and saving.

`ProfileFormRenderer::render()` walks `config('profile.sections')` (personal, school, contact, public,
settings) and renders each block with `ProfileFormElements::{type}()` (BootForm markup). A required field
gets `ui.star`. A "Verify" button next to a field links to `/verification/select_method/{attribute}`.

### Saving: `App\LoginModule\Profile\UserProfile`

`update($request, $fillable)`:

1. builds the data for every fillable attribute; a missing key becomes `null` (unchecked checkbox;
   Laravel 5.4 `only()` semantics kept on purpose);
2. fills and saves the user, clears `login_revalidate_required`;
3. stores the picture (`Image::make` → fit 200×200 → `Storage::put('profile_pictures/{id}.{ext}')` on the
   default disk; `User::picture` returns `Storage::url()` or the default avatar);
4. updates the emails (`updateEmail`): empty → the email row is deleted; new/changed → a verification code
   is generated and mailed;
5. flushes badge data kept in session.

`completed($user)` is true when every attribute the platform requires (plus its recommended ones right
after login, flagged by the `AuthLogin` listener) is filled. Without a platform it is always true.

### The profile page (`ProfileController`)

Routes: `GET|POST /profile`, `GET|POST /profile/username` (middleware `auth`, `merging_accounts`).

| Input | Source |
|---|---|
| Required attributes | client `user_attributes` (only `login` if `login_change_required`); emails dropped for platform-generated accounts |
| Recommended | client `recommended_attributes` |
| Hidden | client `hidden_attributes` that are still empty |
| Disabled | PMS fixed fields (users linked to PMS), `login` when `login_fixed` or changed less than `profile.login_change_available.second_interval` ago, and empty GDPR attributes |
| Unverified | `Verification::unverifiedAttributes()` |
| Rejected by filter | `ProfileFilter` with the client's `attributes_filter` |

Alerts (`resources/views/profile/alerts/`): `filter`, `profile_not_completed`, `verification`,
`revalidation` (merged accounts), `login_change_required`, `pms_redirect`. A JavaScript dialog warns before
changing a verified attribute.

On `POST /profile`: login suggestion (if the login is new and not normalized, the form comes back with a
suggestion), validation, deletion of the approved verifications whose attribute changed, save, then
redirect to `_goto` or to the platform (`PlatformContext::continueUrl()`).

### Login changes

`/profile/username` (`UsernameChangeController`) changes the login, after reauthentication, records the
old login in `username_changes` and is limited by `profile.login_change_available`. Logins not matching
`login_validator.existing` were flagged `login_change_required` (2018) and must be changed before the next
authorization.

### Graduation

`App\LoginModule\Graduation` computes, from `graduation_grade` and the country's end-of-school-year month
(`config/graduation_month.php`, default July, Australia January), the `graduation_year` and the date the
grade expires (`graduation_grade_expire_at`). An expired grade is shown empty so the user updates it.

## Emails

`App\Email`: `role` primary/secondary, `email` (lower-cased), `login_enabled` (can be used to log in),
`code` / `last_code_at` (verification code), `email_revalidate_required` (merged accounts).

- `requireVerification()` generates a 10-char code, stamps `last_code_at` and sends
  `EmailVerificationNotification` (link to `/email_verification?email=…&code=…` plus the code).
- `GET /email_verification` (no auth, `EmailCodeStandaloneController`) approves the email when the code
  matches.
- The `verified` column was dropped in 2018 (verifications moved to the `verifications` table) but
  `Email::requireVerification()`, `UserProfile::updateEmail()` and `VerifiableUser` still read it
  (always null).

### Notification mails

All notifications extend `App\LoginModule\LocalizedNotification`:

- the language is the recipient user's `language` (validated, falls back to `app.locale`);
- `app_name` / `app_url` placeholders are the current platform's name and redirect host (or `app.name` /
  `app.url`);
- subject and body come from `resources/lang/{lang}/notifications/{key}.php`, rendered in the Markdown
  layout `resources/views/notifications/layout.blade.php`.

| Notification | Key | Data | Languages |
|---|---|---|---|
| `EmailVerificationNotification` | `email_verification` | `link`, `code` | en, fr, sl, de |
| `PeerVerificationNotification` | `peer_verification` | `code` | en, fr, sl |
| `ResetPasswordNotification` | `reset_password` | `token`, `login` | en, fr, sl, de, ru |

## Verification

### Concepts

A platform declares which attributes must be **verified** (`oauth_clients.verifiable_attributes`) and
which **methods** it accepts (pivot `oauth_client_verification_method`, with an `expiration` in days, null
or 0 = never). A `verifications` row records one attempt: user, method, attributes, status
(pending/approved/rejected), confidence, message, file, code.

| Method | Verifies | How |
|---|---|---|
| `email_code` | primary_email, secondary_email | code sent by email |
| `email_domain` | role | email address on an official school domain of the user's country |
| `id_upload` | first_name, last_name, birthday, country_code | ID document upload, checked by an admin |
| `classroom_upload` | role | classroom photo upload, checked by an admin |
| `peer` | role | code sent to another person's email |
| `imported_data` | role | created by the import commands only (not public) |
| `user_helper` | all | not public |

### `App\LoginModule\Profile\Verification\Verification`

- Only verifications made with a method attached to the current platform count.
- State of a verification: `REFRESH_REQUIRED` from `expiration - verification.expiration_alert_interval`
  (5 days), `OBSOLETE` when expired, `ACTION_REQUIRED` (pending peer), `IN_PROCESS` (pending), `VERIFIED`,
  `REJECTED`.
- `attributesState($user)` starts from the platform's verifiable attributes and overlays the user's
  verifications (`VERIFIED` wins). It is part of the user API response.
- `authReady($user)`: every verifiable attribute is verified; `AuthorizationAvailable` sends the user to
  `/verification` otherwise.

`Verificator` is legacy code, unused.

### Routes

| Route | Controller | Notes |
|---|---|---|
| `GET /verification` | `Verification\IndexController@index` | methods of the platform, user's verifications |
| `GET /verification/select_method/{attribute}` | `@selectMethod` | goes straight to the method when only one fits |
| `POST /verification/delete/{id}` | `@delete` | deletes one of the user's verifications and its file |
| `GET|POST /verification/email_code` | `Methods\EmailCodeController` | `role`, `code`, `resend=1`; resend limited by `verification.email_code_interval` (60 s) |
| `GET|POST /verification/email_domain` | `Methods\EmailDomainController` | `country_code` → official domains; `role`, `account`, `domain` |
| `GET|POST /verification/id_upload` | `Methods\IdUploadController` | `file`, `user_attributes[]`; a 6-digit code to write on the photo |
| `GET|POST /verification/classroom_upload` | `Methods\ClassroomUploadController` | same, for `role` |
| `GET|POST /verification/peer` | `Methods\PeerValidationController` | `email` (address or login of the peer) |
| `GET|POST /verification/peer_code/{id}` | `@code`, `@storeCode` | `code` received by the peer |
| `GET /verification/imported_data/{id}` | `Methods\ImportedDataController` | information page |

Uploads are stored as `verifications/{random40}.{ext}` on the default disk and reviewed in the admin
interface (`/admin/verifications/edit`, permission `admin.verifications.verify`): status, verified
attributes (the others become `rejected_attributes`), confidence 0–100, message. The file is deleted
after the review.

### Official domains

`official_domains` (country, domain) lists school email domains. `GET /official_domains?country_code=`
returns them as JSON for the verification form; admins manage them in `/admin/official_domains`
(`admin.domains.manager`). `App\LoginModule\TeacherDomain::verify($user)` checks whether one of the user's
emails is on an official domain of their country.

## Personal data (GDPR)

| Route | Behaviour |
|---|---|
| `GET /collected_data` | platforms linked to the account (from its OAuth tokens) and the stored attributes |
| `GET /collected_data/export` | JSON download `login-module-export.json` |
| `POST /collected_data/delete` | refused while a platform is linked; otherwise deletes tokens counters, auth connections, auto-login token, badges, emails, obsolete passwords and verifications, clears every profile attribute except the login, logs out |

`config/gdpr.php` lists personal data attributes (address, city, zipcode, phones): they are hidden from the
platform admin's attribute choices and, in the profile, cannot be newly filled once empty.

Platforms unlink an account with `platform_api/accounts_manager/unlink_client` (logged in `user_deletions`).

## UI

`config/ui.php`: required marker, avatar size and default, upload limit, default footer
(`PlatformHelper::platformFooter()` uses the client's `footer` first). Layouts:
`resources/views/layouts/popup.blade.php` (user pages, with the platform name and cancel link),
`admin.blade.php`; tabs visibility from `PlatformHelper::navTabVisible()`.
